Senin pagi, admin tunjangan dari Keuangan mengisi Rp250.000 ke 100 akun karyawan. Di v1 belum ada layar admin. Admin mengunggah CSV dari sistem HR lewat skrip, dan backend yang memutuskan apakah file itu diterima.

Dari sisi admin, top-up adalah satu file dan satu perintah. Di backend, file itu diperiksa baris demi baris dulu, baru 100 saldo diubah bersama-sama. Peta di bawah mengikuti satu unggahan Senin pagi dari rekaman lab.

<Blok nama="Yang diminta PRD" buka>

| Prioritas | Fitur | Keterangan |
|---|---|---|
| P0 | Top-up tunjangan oleh admin | Admin mengunggah daftar nama dan nominal; saldo masuk ke 100 akun |

PRD juga menulis kebutuhan admin: "isi saldo 100 orang sekali klik tiap Senin". Aturan Pak Hadi berlaku di sini juga: tidak ada angka yang berubah tanpa catatan siapa, kapan, kenapa.

<Blok nama="Konsep yang akan dibutuhkan">

- [[B3.1]]: kenapa 100 perubahan harus dibungkus satu unit.
- [[B6]]: memeriksa input sebelum menyentuh uang, dan format error yang bisa dibaca admin.
- [[B5.3]]: hanya admin yang boleh top-up; Budi mendapat `403`.
- [[t1-adr-transaction]]: catatan "siapa, kapan, kenapa" sebagai keputusan, bukan kebiasaan.
